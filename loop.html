LOOP: what happens after you hit Enter in Claude Code

Free cheat sheet from Gelbi AI. Keyword: LOOP.

How to read this page:

  • DOC = stated in the official Claude Code docs. The source URL is on the line.
  • SUGGESTION = my idea. It is not from the docs. Try it, do not treat it as a documented fact.

Docs checked: 2026-11-12. Re-check a detail before you rely on it. The docs do not describe the Enter key itself, only what Claude does with your prompt.

1. The loop in one picture

DOC When you give Claude a task it works through three phases: gather context, take action, verify results. "These phases blend together." Claude uses tools the whole way through, and the loop repeats until the task is complete.
https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop

YOUR PROMPT
    |
    v
MODEL (reasons, picks a tool)  <-------------+
    |                                        |
    v                                        |
TOOLS: READ / EDIT / BASH ---> RESULT ---> CONTEXT
                                 (feeds the next decision)
  • DOC Two parts power the loop: models that reason and tools that act. Claude Code is the layer around the model that provides the tools and manages the context the model sees (the "agentic harness").
    https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop
  • DOC "Without tools, Claude can only respond with text." Each tool use returns information that feeds back into the loop, informing Claude's next decision.
    https://code.claude.com/docs/en/how-claude-code-works#tools
  • DOC The loop adapts. A question about your codebase might only need context gathering. A bug fix cycles through all three phases repeatedly.

2. The docs example, step by step

DOC For "fix the failing tests", Claude might: run the test suite, read the error output, search for the relevant source files, read those files, edit the files to fix the issue, run the tests again to verify.
https://code.claude.com/docs/en/how-claude-code-works#tools

DOC Tools in the reference table: Read reads file contents (no permission needed in Manual mode), Edit makes targeted edits (permission needed), Bash runs shell commands in your environment (permission needed).
https://code.claude.com/docs/en/tools-reference

3. How to steer the loop (the exact keys and commands)

  1. DOC Stop it now: press Esc. The running tool call is canceled and Claude waits for your next instruction.
  2. DOC Correct it without stopping: type a correction and press Enter. It is queued; Claude reads it as soon as its current tool calls finish, within the same turn.
    https://code.claude.com/docs/en/how-claude-code-works#interrupt-and-steer
  3. DOC Change what it may do without asking: Shift+Tab cycles permission modes (Auto, Manual, Accept edits, Plan).
    https://code.claude.com/docs/en/how-claude-code-works#control-what-claude-can-do
  4. DOC Plan first: /plan <description> enters plan mode: Claude explores and proposes a plan without editing your source files.
    https://code.claude.com/docs/en/commands and https://code.claude.com/docs/en/permission-modes
  5. DOC See what fills the context: /context. Free space with /compact [instructions].
    https://code.claude.com/docs/en/commands
  6. DOC Side question, no history pollution: /btw <question>.
    https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw
  7. DOC Keep it going toward a finish line: /goal <condition>. After every turn a separate model checks whether the condition holds.
    https://code.claude.com/docs/en/goal

4. Prompt pack (all SUGGESTION unless marked)

  1. Fix the failing tests. (the docs example prompt). Watch which tools it uses, in what order.
  2. /plan fix the auth bug (the /plan <description> form is DOC; the task is my example).
  3. Run the auth tests after, and keep going until they pass. (this wording is quoted from the best-practices page, DOC https://code.claude.com/docs/en/best-practices)
  4. /goal all tests in tests/auth pass and lint is clean (quoted from the same page, DOC)
  5. Show me the exact command you ran and its output. The docs recommend asking Claude for evidence, not just "all tests pass".
  6. Before you edit anything, tell me which files you read and what you learned.
  7. Explain what each step of this change does before you run the next one.
  8. /btw what was the name of that config file again? (the example from the docs, DOC)

5. The 10 best ways to put the loop to work (all SUGGESTION, each uses a documented control)

  1. Stop a wrong turn early. Press Esc the moment you see it heading the wrong way.
  2. Redirect mid-task. Type the correction and press Enter. No need to start over.
  3. Ask a pure question. Questions about your code may only need the context-gathering phase.
  4. Give it a way to check itself. Name the test or command that proves the work is done, so the verify phase has a target.
  5. Plan before a big change. /plan, then review the plan before it edits anything.
  6. Run a long task to a finish line. /goal with a condition Claude's own output can show, such as a test result.
  7. Keep an eye on the context. /context on a long session, /compact with a focus when it fills.
  8. Tune the permissions. Cycle modes with Shift+Tab depending on how closely you want to watch.
  9. Ask without derailing. /btw for a side question while the work continues.
  10. Rewind a bad run. /rewind (see the REWIND cheat sheet) if a loop went somewhere you did not want.

6. Extra things you can do

  • DOC The context window holds: your conversation history, file contents, command outputs, CLAUDE.md, auto memory, loaded skills and system instructions. Put persistent rules in CLAUDE.md, not in the early conversation, because early instructions can get lost when Claude compacts.
    https://code.claude.com/docs/en/how-claude-code-works#the-context-window
  • DOC A log of the loop exists. Each message, tool use and result is written to a plaintext JSONL file under ~/.claude/projects/.
    https://code.claude.com/docs/en/how-claude-code-works#work-with-sessions
  • SUGGESTION Open one of those JSONL files in an editor to see the tool calls of a past run in order. (The file format is not documented here; I did not check its fields.)
  • DOC Extensions sit on top of the loop: skills, MCP, hooks and subagents.
    https://code.claude.com/docs/en/how-claude-code-works#tools

7. What this page does not claim

  • Nothing about how fast the loop runs or how many turns a task takes. The docs say "dozens of actions" can be chained, but give no figures for a typical task.
  • Nothing about how the model decides which tool to use. The docs only say Claude chooses "based on your prompt and what it learns along the way".
  • Not every prompt uses a tool.
  • The "Enter presses" counter in the video is a joke, not a statistic.
